# PRD · 推进 Agent 化：M2 清理 → L3 验证 → L4 狗食 → M5 蓝图

## 背景

2026-07-14 评估发现项目在成熟度阶梯上的实际位置为 **L2 收尾 / L3 起步**，距 `01-vision.md` 目标有以下关键差距：

1. **M2 未完全关闭**：旧编排层 `services/writing_agent/` 58 文件 / 21,702 LOC 仍存活，被 v1 端点引用
2. **L3 验证缺失**：护栏代码就绪但无人值守 10 章狗食未执行
3. **L4 验证缺失**：记忆工具就绪但 50 章一致性狗食未执行
4. **M5 未规划**：百万字专业化无具体方案

## 目标

将项目从 **L2 收尾** 推进到 **L4 验证通过**，并产出 M5 可执行蓝图。

## 子任务拆分

| # | 子任务 | 交付物 | 可独立验证 |
|---|--------|--------|------------|
| 1 | M2 清理收尾 | 删除旧编排层 → `git grep` 零命中 | 后端回归全绿 |
| 2 | L3 自治验证 | 无人值守 10 章 + 熔断/压缩验证 | 脚本全部通过 |
| 3 | L4 记忆狗食 | 50 章一致性验证 + 记忆召回质量 | 零硬性漂移 |
| 4 | M5 蓝图 + 文档 | M5 PRD/design + 全部文档更新 | 文档合入 main |

## 跨子任务验收

- 每个子任务完成后，后端 730 测试 + 前端 576 测试保持全绿
- `main` 分支任何时刻可用
- 狗食发现的问题记录进 `05-progress-tracker.md` 问题清单，修复优先于新功能

## 约束

- 不新增功能特性（清理和验证为主）
- 不修改已工作的新 agent 内核（`loop.py`/`harness.py`/`tooling.py`/`guards.py`/`events.py`）
- 不引入新的外部依赖
- 旧编排层删除前，先确保新架构已覆盖对应能力

## 不做

- 不在此轮优化新 agent 内核性能
- 不修改数据库 schema
- 不触及前端设计系统
