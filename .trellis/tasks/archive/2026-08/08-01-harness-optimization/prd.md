# P0 Harness 系统化优化

## Goal

在 M5 200 章长程实验（201 章 PASS，但暴露第二部模板化注水、无终局、格式退化）之后，
系统性强化 agent 内核 harness 层，使模型在长程写作中走偏时能被接住、纠正、恢复：
容错兜底、写作质量约束（终局/格式/重复/伏笔）、上下文注入工程、可观测性。
参照 hermes-agent / openclaw / openhuman 三项目模式（harness-engineering-list.md + 两份 200 章评审）。

## 全局约束

- 每项改动遵循：**先在 `backend/tests/agent/` 补测试 → 再改内核 → 跑全量 pytest + vitest → 独立 commit**（清单 §三）
- 内核模块（`app/agent/`）不得依赖具体持久化技术（CADR-005）；工具层（`app/tools/`）可访问 DB
- 所有错误信息写给模型看（tooling.py 模块约定）：说明错在哪、下一步可以怎么做
- 不引入新依赖库；格式校验/相似度检测用确定性规则 + 标准库
- 系统提示词强化「只能调用工具目录中的工具」归入 T2（工具目录强化）与 T6（事实表）分别落地
- 保持现有 API/事件契约不变，新增事件/字段向后兼容（JSONL 会话日志是真相源）
