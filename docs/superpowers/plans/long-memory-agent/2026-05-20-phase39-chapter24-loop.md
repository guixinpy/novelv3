# Phase39 Agent Constraint Orchestration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop relying on user-side long prompt constraints and make the Writing Agent assemble chapter constraints from existing story state, Athena/world model, storyline, foreshadowing, longform memory, and retrieval.

**Architecture:** Treat Chapter 24 as a diagnostic sample, not the main objective. Add an Agent-side constraint context package that is injected into outline-window expansion and chapter generation. Use the package to make unresolved foreshadowing, recent chapter state, pending story direction, and premature-reveal risks visible to the model before it writes.

**Tech Stack:** FastAPI TestClient, SQLAlchemy models, `prompting.providers.*` context blocks, Writing Agent run service, Athena longform memory/retrieval, targeted pytest.

**Length Policy:** `2000+` is an elastic quality target. The Agent should use the project target band as a soft range and only block obvious shrinkage or runaway length.

## Course Correction

This phase was corrected after the initial Chapter 24 outline expansion exposed the wrong operating mode:

- A user/operator supplied detailed external constraints.
- The generated outline still contained premature or incorrect content:
  - "左臂内侧似乎是 N-07";
  - `G-07` treated as a lower-city lab area instead of a bounded evidence lead;
  - buying special fog crystal to open access controls.
- This proves the current system is not yet acting as a long-memory writing Agent. It is still too dependent on manual prompt steering.

Phase39 will therefore focus on the Agent constraint chain, not on producing another chapter by hand.

Additional goal clarification captured during the phase:

- The goal's center is upgrading novelv3 into a domain Agent system.
- Existing modules must be toolized so the Agent can call them as capabilities.
- Reference projects `openclaw`, `hermes-agent`, and `openhuman` should be studied for Agent engineering patterns, especially tool contracts and orchestration loops.
- Novel generation remains the pressure-test loop, not the primary output of the goal.

## Task 2: Design the Minimal Agent Constraint Package

- [x] **Step 1: Define constraint package responsibilities**

The package must be generated by the system, not by long user `command_args`.

It should include:

- current chapter target;
- previous chapter end-state;
- unresolved foreshadowing relevant to the current chapter;
- upcoming story milestones relevant to the current chapter;
- known world facts for entities mentioned in recent context;
- explicit premature-reveal cautions derived from unresolved foreshadowing and current chapter position;
- source metadata for trace inspection.

- [x] **Step 2: Define non-goals**

This phase must not:

- build a perfect long-memory Agent in one step;
- hard-code the full Chapter 24 solution as a system rule;
- replace Athena, world model, storyline, or retrieval;
- continue generating chapters by manually writing long constraints.
