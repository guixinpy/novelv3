## 6. 重要经验教训

1. **文档声明必须实测**：本项目历史文档（progress-tracker、commit message）存在虚标，接手后先跑测试、查代码、核对会话日志，不要信文档。
2. **长任务不傻等**：运行超过预期时间先查进程/日志/数据库，优先怀疑代码问题（本次实验 4 次中断都是主动排查发现根因）。
3. **模型行为 ≠ bug**：第 100 章模型拒绝写番外是规范生效（正确行为），用「第二部」模式解决，而不是改模型。
4. **压缩是长程实验的生命线**：75% 阈值触发 + 头尾保护 + 摘要质量（跳过旧摘要、纳入最近写入）缺一不可；压缩后必须清洗孤立 tool 消息。
5. **多代理消息投递不稳定**：spawn 初始消息曾全部丢失、部分 followup 也丢失；子代理任务失败时检查其 final 是否真的收到任务，必要时主会话直接执行。
6. **参考项目更新方式**：快照目录无 `.git`，更新 = 重新 clone 到临时目录（排除 `.git` 后替换），并在 README 更新 commit。
