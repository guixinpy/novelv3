## 一、我们要打造什么

### 一句话定义

**novelv3 是一个专精网络小说创作的长期记忆 Agent 系统。** 它以对话为唯一交互入口，具备自主工具编排、长期记忆管理和分层次子代理能力，能够支撑百万字/千章级别的长篇小说从设定、大纲到正文、审稿、修订的完整创作生命周期。

### 定位澄清：Agent，不是工具

| 维度 | 传统 AI 写作工具 | novelv3 Agent |
|------|-----------------|--------------|
| 交互模式 | 用户手动触发每个功能 | 对话驱动，Agent 自主编排工具 |
| 记忆方式 | 依赖上下文窗口 | 结构化长期记忆（世界模型 + 检索 + Memory Tree） |
| 世界一致性 | 靠 prompt 约束 | 多层次世界模型 + 提案审批 + checker |
| 操作审计 | 无 | 全链路 trace |
| 错误恢复 | 手动重写 | 版本回滚 + 修订闭环 |
| 可扩展性 | 加 prompt | 注册工具 + worker + 子 agent |

### 最终用户画像

- 网络小说作者（百万字级长篇连载）
- 需要的是"能记住前面写了什么、能自主推进创作、能审稿和修订"的协作伙伴
- 不是"每次都要重新描述需求"的对话机器人

### 2.2 各层职责

| 层级 | 职责 | 关键约束 |
|------|------|---------|
| Chat Interface | 唯一用户交互入口 | 所有操作通过对话触发，不暴露独立功能按钮 |
| Dialog Control Plane | 理解用户意图，生成执行计划 | 计划必须可审批、可追溯 |
| Agent Orchestration | 执行工具调用，检测循环，触发恢复 | 必须审计每次模型调用 |
| Tool & Worker | 具体能力实现 | 每个能力封装为可注册的工具 |
| Long-term Memory | 超越上下文窗口的信息管理 | 分层存储，按需检索 |
| Data & Recovery | 持久化与容错 | 错误可回滚，变更可追踪 |

## 三、核心设计理念

### 3.1 对话驱动 (Dialog-Driven)

**所有操作都通过对话入口发起**。用户不需要知道"Athena 世界模型"或"检索系统"的存在——只需要在对话中说"写第 10 章"或"审稿第 3 章并修订"。Agent 自主判断需要调用哪些工具、组合哪些能力。

当前状态：对话意图路由已部分实现（IntentRouter → DialogIntentPlanner → WritingAgentPlan），但覆盖面还需要扩大。

### 3.2 结构化长期记忆 (Structured Long-term Memory)

**百万字小说不能靠上下文窗口**。novelv3 通过三层记忆系统实现"记忆":

1. **世界模型 (Athena)**：结构化世界事实（角色、地点、事件、关系），带提案审批和 checker 校验
2. **检索系统 (Retrieval)**：基于 embedding 和全文搜索的章节内容检索
3. **Memory Tree（目标态）**：分层摘要树（卷→章→节），支持按需展开/收起，借鉴 openhuman

当前状态：Athena 和 Retrieval 已有较完整实现，Memory Tree 已在 `writing_agent` 中搭建框架。

### 3.3 提案审批 (Proposal-Approval Gate)

**AI 不能直接修改世界真相**。任何对世界模型的修改必须走提案→审阅→通过/拒绝流程。

当前状态：Athena 的 WorldProposalBundle 机制已实现。

### 3.4 全链路可审计 (Full Audit Trail)

**每次 AI 调用必须有 trace**。用户能看到 AI 吃了什么 prompt、用了什么上下文、产出了什么。

当前状态：AIModelCallTrace 系统已实现，前端有 ModelTraceDrawer。

### 3.5 可恢复 (Recoverability)

**允许犯错，但必须能回滚**。章节可以回滚到旧版本，世界模型提案可以拒绝或回滚。

当前状态：Version/rollback + ChapterRevision 机制已实现。

### 3.6 真实压力测试驱动 (Dogfood-Driven)

**不以"架构更完整"作为完成标准**。每个改动必须由真实小说生成的失败暴露来触发，必须有可复现的诊断输出。

当前状态：longform smoke 测试已存在，但需要持续的真实长篇 dogfood。

## 四、Agent 化成熟度模型

我们将 Agent 化程度分为 5 个等级，用于评估每个模块的当前状态和目标状态：

| 等级 | 名称 | 含义 |
|------|------|------|
| L0 | Static Tool | 被动工具，用户手动调用 |
| L1 | Triggered | 有触发机制，但逻辑硬编码 |
| L2 | Rule-based Agent | 基于规则的自主决策 |
| L3 | LLM-guided Agent | LLM 参与决策和编排 |
| L4 | Self-improving Agent | 能从反馈中学习和优化 |
| L5 | Autonomous | 完全自主，仅需用户确认关键决策 |

当前项目 Agent 化目标：
- **Hermes**：L3 → L4（当前 L2-L3，目标自主诊断+建议+执行）
- **Athena**：L2 → L3（当前依赖规则检查，目标 LLM 驱动的语义检查）
- **Writing**：L2 → L3（当前基于模板，目标 LLM 自适应风格和上下文）
- **Review**：L1 → L3（当前基础检查，目标多维度语义审稿）
- **Memory**：L2 → L3（当前检索+简单存储，目标 Memory Tree + 主动召回）

## 六、不做的事（防止范围蔓延）

1. **不做通用的 AI Agent 框架**：novelv3 只服务网文创作场景
2. **不做多用户 SaaS 平台**：当前是单用户、单项目为主
3. **不做实时协作编辑**：不是 Google Docs
4. **不做社交/发布功能**：创作工具，不是内容平台
5. **不过度抽象**：不为"未来可能的需求"添加抽象层
6. **不重写已有稳定模块**：除非被真实问题触发

## 七、成功标准

### 第一阶段（当前→短期）

- [ ] Agent 能理解完整的网文创作意图集合（设定→大纲→正文→审稿→修订→恢复）
- [ ] 所有 AI 调用通过 trace 可审计
- [ ] 工具循环有熔断保护（借鉴 openclaw 五级检测）
- [ ] Memory Tree 实现基础分层摘要（卷→章两级）

### 第二阶段（中期）

- [ ] Agent 能自主推进多章连续写作（无需每章手动触发）
- [ ] 审稿能发现跨章节矛盾（角色死亡后复生、物品丢失、时间线矛盾等）
- [ ] 上下文管理实现智能压缩和按需展开
- [ ] 子 Agent/Worker 分工明确（写作 worker、审稿 worker、记忆 worker）

### 第三阶段（远期）

- [ ] 支持百万字/千章级长篇的完整创作
- [ ] Agent 能从作者反馈中学习并调整风格
- [ ] 世界模型在千章规模下保持一致性
- [ ] 真正意义的"长期记忆"——跨 session、跨项目的知识积累
