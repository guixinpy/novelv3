# 04 · 开发规则

继承旧版 `04-development-rules.md` 中被验证有效的纪律（重构期绞杀式迁移规则已完成使命，见归档）。

## 1. 分支与合并

- 重构完成（arch-refactor 已并入 `main`）后，开发直接在 `main` 分支进行。
- 提交前跑全量测试 + ruff；提交信息含「事实 + 影响面 + 验证」摘要。
- 推送远端前确认工作区干净、无未提交改动。

## 2. 变更纪律

1. **删除即彻底**：决定删除的模块一次删干净（代码 + 端点 + 调用方 + 测试 + 文档引用），不留注释掉的尸体、不留「以防万一」的兼容垫片。删除前用 `git grep` 确认零引用。
2. **每个 session 结束时仓库可运行**：`pytest` 全绿 + ruff 全过，否则不结束。
3. **外科手术**：只改任务要求的代码；发现无关死代码先提出、不顺手删。

## 3. 依赖方向

```
api → agent → tools → domain → models
```

- 上层可依赖下层，禁止反向。`domain/` 不得 import `agent/` 或 `tools/`。
- 例外：`tools/` 可以 import `agent/` 的类型与注册机制——`agent/` 对 `tools/` 而言是框架库；反向（`agent/` import `tools/`）仍然禁止，工具注册表通过依赖注入进入循环。
- `tools/` 是 `domain/` 的薄封装：工具函数体超过 ~50 行说明逻辑该下沉到 domain。
- 新内核 `agent/` 不依赖任何小说领域概念（保持「通用 Agent 内核 + 领域工具」的分界，这是「先成为合格 Agent、再专业化」的结构保证）。

## 4. 测试纪律

- **新内核（agent/、tools/registry）必须 TDD**：循环终止、预算、风险检测、压缩、审批门——这些是护栏，护栏本身必须被测试钉死。
- 工具实现层：每个工具至少覆盖「正常路径 + 一个模型可恢复的错误路径」（错误信息是给模型看的，测试要断言其可操作性）。
- LLM 调用一律用 fake provider 测试；涉及真实模型质量的验收（如记忆摘要质量）走 dogfood 实验，不进单测。
- **文件预算**（继承旧 ADR-011）：源文件软上限 500 行、测试文件软上限 1000 行；超限即拆分。旧版 8000 行测试文件的教训不重演。
- 删除旧模块时同步删除其测试，禁止留「跳过的测试」。

## 5. 验证命令（每次声称完成前必须实际运行）

```bash
# 后端全量回归 + lint
cd backend && python -m pytest tests/ -q
cd backend && python -m ruff check .

# 前端（重写后）
cd frontend && npm run build && npm run test
```

## 6. 工具设计规范

1. 工具描述写给模型看：说明何时该用、何时不该用、参数含义。
2. 结果结构化且自包含：模型不应需要二次调用才能理解结果。
3. 错误可恢复：返回「错在哪 + 模型下一步可以怎么做」，而非裸异常堆栈。
4. 幂等优先：写入类工具尽量幂等（确定性 ID / 版本号），允许循环重试。
5. 权限显式声明：`read` / `propose` / `write`，新工具默认最低权限。
6. 一组相关工具一个文件，文件内自注册；禁止中央工具清单文件。

## 7. 提示词管理

- 系统提示三层结构（稳定/上下文/易变）是硬约束：改动稳定层须意识到 prefix cache 失效成本。
- 提示词版本化：重要提示词改动在 commit message 中注明，dogfood 对比时可回溯。

## 8. 文档纪律

- **设计定稿**（需求讨论 + 评审后）写入 claude-guide（`09`/`11` 编号模式），实现后更新文档状态。
- 重要架构决策当场写入 `06-decisions.md`（一段话即可，拒绝事后补写）。
- **活跃进度**由 trellis 任务承担，不再维护进度日志文档（旧进度日志已归档）。
- 一次性记录（dogfood 报告、实验数据）放 `docs/archive/`，不污染 claude-guide。
- 已完成阶段的规划/研究文档归档到 `docs/archive/claude-guide-legacy/`，不留占位。

## 9. 处理与用户的协作

- 删除超出本文档清单的模块、修改数据库 schema（删表/删列）、引入新外部依赖：先询问用户。
- dogfood 需要消耗真实 API 额度的实验：说明预估用量后再执行。
