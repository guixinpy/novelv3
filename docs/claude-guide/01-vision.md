# 01 · 愿景与项目重新定义

## 北极星目标

**novelv3 是一个专精于长篇网文创作的 LLM Agent。**

最终形态：作者用自然语言与 Agent 协作，Agent 能自主完成「设定 → 大纲 → 逐章写作 → 自检 → 修订」的完整循环，在百万字、上千章的尺度上保持人物、世界观、伏笔的一致性，并在质量下滑或行为异常时自动停下、诊断、恢复。

## 重新定义：是什么 / 不是什么

### novelv3 **是**：

1. **一个真正的 Agent**——由模型驱动的工具调用循环：模型看到工具目录，自己决定调用什么、读什么、写什么、何时结束。规划、反思、恢复主要由提示词和预算约束涌现，而不是由 Python 脚本预先编排。
2. **一个领域专家**——它的工具、记忆、提示词全部围绕长篇小说创作设计：章节读写、世界观查询与提案、记忆树、一致性检查、伏笔追踪。
3. **本地优先的单用户应用**——SQLite、单进程、面向一位作者。不做多租户、不做分布式。

### novelv3 **不是**：

1. ❌ 不是「带 AI 按钮的小说管理后台」。CRUD 界面只服务于作者确实需要直接编辑的内容，其余交互都通过与 Agent 对话完成。
2. ❌ 不是确定性工作流引擎。**禁止**再出现「意图分类 → 查表选 plan → 按脚本逐步执行」的模式（旧 `intent_router.py` + `planner.py` 的死路）。意图理解是模型的工作。
3. ❌ 不是通用 Agent 框架。我们只为「写小说」这一个场景构建，不做插件市场、不做多平台接入、不做通用编排框架。

## 为什么翻转（历史教训）

上一版（Codex 时期）走到了「Agent 化 70%」的位置后停滞，根本原因：

- **控制反转没有发生**。LLM 只是 `chat/completions` 的文本生成器（无原生 tool-call、无流式），所有「Agent 行为」由 ~129 个 Python 模块模拟。每加一种能力就要新写 descriptor/adapter/execution 三层，6 条生成管线 80% 重复。
- **复杂度长在了错误的方向**。意图路由 2400 行正则、run_service 2015 行上帝模块、测试 6.8 万行——大量代码在为「脚本化编排」这个本应不存在的层兜底。
- **但护栏是真金白银**。真实 dogfood（《灯塔旧回声》）暴露的问题——工具乒乓循环、章节超长、人名漂移、上下文爆窗——催生了五级循环风险检测、提案审批门、上下文预算、溯源契约。**这些经验必须保留，在新循环里重建。**

## 成熟度阶梯

| 等级 | 描述 | 验收方式 |
| --- | --- | --- |
| **L1 能对话** | 新内核跑通：模型驱动循环 + 流式 + 原生工具调用，能通过对话读写项目数据 | 对话完成一次章节读取与修改 |
| **L2 能干活** | 全部核心能力以工具形式接入，旧编排层删除，前后端瘦身完成 | 对话完成「设定→大纲→单章生成→修订」全流程 |
| **L3 能自治** | 预算、循环风险、审批门、断点恢复在新循环内生效 | 无人值守连续生成 10 章，异常时自动停下并给出诊断 |
| **L4 能记忆** | 记忆树 + 实体索引 + 多通道召回，跨章一致性可验证 | 50 章 dogfood，人物/设定零硬性漂移 |
| **L5 能写百万字** | 长程质量趋势、伏笔闭环、弧线规划进入循环 | 续写既有长篇 ≥200 章且质量趋势不下滑 |

当前位置：**L3 验证通过 / L4 部分验证（37章，弧线崩塌问题已识别） / M5 蓝图完成**。路线图见 `03-roadmap.md`。
